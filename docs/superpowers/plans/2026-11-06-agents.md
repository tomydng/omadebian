# Agents for GNOME Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement task by task. User requested direct execution; do not interrupt for further design choices.

**Goal:** Install an Omarchy-inspired native Agents quota panel, prioritizing Claude's remaining percentage.

**Architecture:** A GJS panel button renders display-safe JSON from a bounded Python collector. Provider adapters normalize remaining percentages and reset times; private cache preserves last-known values on temporary failure.

**Tech Stack:** GNOME Shell 48/GJS, Python 3 standard library, GLib/Gio/St, unittest.

**Spec:** docs/superpowers/specs/2026-11-06-agents-design.md

## Global Constraints

- Native GNOME 48; Claude first, Codex second.
- Display remaining quota, not used percentage or token-derived estimates.
- No credentials in output/cache/logs; no inference that unknown quota is 100%.
- Bound provider calls and subprocess lifetime; no synchronous networking in GNOME Shell.
- Preserve the current desktop session and other extensions.

## Review Focus

- Missing, nonfinite, boolean or out-of-range percentages must not invent allowance.
- Failed auth or network must retain clearly marked, correctly scoped last-known values.
- Multiple Codex quota buckets must not double-count the legacy bucket.
- Disable/re-enable during a refresh must not orphan a process or update destroyed actors.
- New-extension discovery on Wayland must not restart the user's desktop.

**Interfaces:** `claude_windows(payload)`, `codex_windows(payload)`, `collect(force=False)` produce `{updatedAt, providers:[{id,name,plan,status,message,windows:[{id,label,remaining,resetsAt}],fetchedAt}]}`.
